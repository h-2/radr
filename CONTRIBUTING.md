# Contributing

Thanks for wanting to contribute! Before starting to work on something, it might be best to reply to the issue that you want to work on (or open a new one!).


## Be excellent to each other

We want this project to be a place where everyone's excellent to each other. So far, this is the only rule. That may change if the project grows.


## LLM assisted contributions

This repository adheres to the [LLVM AI Tools Policy](https://llvm.org/docs/AIToolPolicy.html).

As of summer-of-2026, almost all code in this repository has been written by organic, grass-fed humans :cow: Since we like programming, this will likely remain the default for core library code. But we are not against LLM contributions out of principle.

However, the following is currently **reserved to humans** without exception:

  * Project communication: discussions on Github, opening or replying to PRs or issues, e-mails...
  * The documentation in the docs folder.

For code contributions and inline code documentation, follow the *as-if* rule, i.e. the person submitting code must have written the code themselves or be able to act in every way *as-if* they had written the code themselves. This includes being able to explain every line and being legally allowed to submit the code under the library [licensing terms](./LICENSE.md).

We highly recommend that contributions to the core library be written by humans, especially when contributing to the project for the first time. LLM-assisted pull requests must contain reasoning by the human opening them, and any LLM generated reasoning must follow after and be clearly marked as such.

To show that you are acting in good faith and in adherence to this policy, we suggest that LLM-assisted PRs be followed up immediately with a short code review by the submitting human, detailing their own understanding of the diff and highlighting sections of particular importance.
